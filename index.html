Task 1: Drawing Single-Color Triangles

Rasterizing a triangle means determining the pixels that lie within it. First, vertices are put in a consistent order so that clockwise and counter-clockwise triangles are handled the same way. Next, select the set of pixels that lie within the triangle's bounding box, which is an area determined by the vertex positions. This limits the scope because it is impossible for any pixels outside the bounding box to be covered by the triangle. Each pixel within this box is then sampled using its center point and checked for whether that point is inside the triangle. A point is considered inside the triangle if it lies on the inner side of all three edges. Points that are exactly on an edge are considered to be inside the triangle.

Our implementation first computes the triangle's bounding box from the smallest and largest x/y coordinates of its vertices. It then loops over every pixel in that box, tests whether the pixel's center lies on the inner side of all three edges, and fills the pixel with the triangle's color if it does. This algorithm is not worse than one that checks each sample within the bounding box, because checking each sample within the bounding box is exactly what our implementation does, with a constant amount of work per pixel.

Task 2: Antialiasing by Supersampling

The main data structure is the sample buffer, which is std::vector< Color > that stores a floating-point color for each sample. Each pixel's samples are stored next to each other, so when pixels are laid out row by row, a pixel's samples form one contiguous block. For triangles, we kept Task 1's algorithm with the supersampling modifications. Instead of running the tests on just one point in each pixel, we tested on sub-pixel sample points within each pixel. Each covered sample gets written into the sample buffer with the triangle's color.
Supersampling is useful because sampling once per pixel creates jagged edges and makes thin shapes break apart as pixels are only classified as fully colored or not colored at all. Supersampling allows partial coverage, so pixels along an edge can get blended colors. That smooths the edges and keeps thin shapes connected. As a result, at sampling rate 1, the tip of the skinny magenta triangle breaks into disconnected pieces, because it's thinner than a pixel and most pixel centers miss it. At rate 4, more of the tip gets picked up, and partly covered pixels show lighter shades of magengta, so it starts to read as a contiguous line. This continues with greater sampling rates. At rate 16, the tip fades out smoothly because we can represent many more levels of partial coverage.
